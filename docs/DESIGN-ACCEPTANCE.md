# 设计系统验收与细节画廊

本文件说明优化分支的验收入口与检查方法，不代表已发布，也不代替最新 CI 结果。

## 体验入口

`#/home` 是产品首页，`#/themes` 是主题实验室。三套风格为 Minimal Pro / Tech Noir / Glass，每套有深浅两种配色，密度独立设置。完整主题与安装约定见 DESIGN-SYSTEM.md。

主题实验室在原有交互工作台下新增“设计细节画廊”，包含三个面板：基础控件、AI 执行状态、表面与变量。切换面板不卸载其内容，切换风格不清空当前草稿、原生选项或演示反馈；刷新页面不会持久化业务示例数据。

## 十个观察点

1. 按钮：主次层级、六种已有 variant、三种尺寸、加载与禁用。
2. 输入：默认与 filled、只读、禁用、错误；说明关联到真实输入框。
3. 选择：普通与卡片选项、首行对齐、长中文、整组禁用、原生单选互斥。
4. 设置：原生 Select、多行 Textarea、即时 Switch 与语义 Badge。
5. 工具卡片：七种可切换状态、模拟审批、失败提示、重试和拒绝。
6. 状态语义：完成、失败、拒绝、取消分开说明，不只依赖颜色。
7. 表面：标准、elevated、inset 和显式 glass；非交互卡片不做假悬浮反馈。
8. 导航：segmented、underline 和 pills 三种 TabsList 外观，保持键盘语义。
9. 变量：色板直接从当前 CSS 变量读取前景/背景对，不维护另一张硬编码色表。
10. 接入：跳转实际组件页，查看复制代码、公开类型和“复制给 AI”。

其中部分按钮只用于静态外观对照，页面有明确说明。保存、选项和审批样本仅改变本地状态，禁止将本页模拟行为解释为模型连接或真实工具授权。

## 本轮样式修正

主按钮 hover 使用不透明混色，不再用 alpha=0.88 把浅色 Tech 的蓝色背景混成更浅的颜色。测试比较文字与纯色/渐变端点的对比度；非标准宿主品牌色仍须自行检查。

降低透明度、减少动画和打印规则匹配根主题选择器的优先级，避免 `:root[data-ui-style="glass"]` 覆盖系统偏好。Glass 在降低透明度时使用不透明表面与零模糊，打印时去掉主题阴影。

## 执行验收

单元交互：`pnpm test`。浏览器验收在 `.github/workflows/ui-browser.yml`，隔离安装 Playwright，并执行既有布局、Vite UTF-8、三皮肤及新增 `scripts/check-design-specimens.mjs` 检查。

新增脚本在真实 Vite preview + Chromium 中遍历三皮肤 × 双明暗 × 375/768/1440px。检查三个面板的横向溢出、七种工具状态、审批失败恢复、草稿保留、主按钮默认/hover 对比度，以及 Glass 系统偏好和打印降级。截图与测量保存在 Actions 产物的 specimens/ 中。

这不是完整 WCAG 认证、所有浏览器验收或成熟的像素基线。发布前仍须解决既有 assistant-ui 无锁新安装 peer 冲突，并让 test:package 完整通过；本轮不降低严格检查、不改运行时和版本、不合并或发布。

## 官网与文档重设计验收

运行 `node scripts/check-site-redesign.mjs`（与现有脚本一样需要 UI_BROWSER_ROOT）。
检查 375 / 768 / 1440px 的浅深色首页、文档、导航宽度；根路径进入首页；真实表单、单选和 Switch；搜索的键盘选择、Enter 导航、Esc 关闭与焦点恢复；桌面分组折叠、过滤与正文目录。产物 `site-redesign/` 保存原始视口截图和结果，不把元素截图当作完整页面。

设计原则：一个强调色、较大留白、真实组件而非假产品截图；首页承接产品介绍，复杂工作台留在主题实验室；文档遵循说明、预览、导入、使用约定、API、源码的顺序。新样式不修改公开 React API、事件或包版本。

单元测试 `site-redesign.test.tsx` 验证路由、原生表单、搜索、侧栏和目录数据同源。既有布局、三风格、对比度、UTF-8 与包消费检查均保留；必须根据实际 CI 结果报告，通过本项不代表包消费检查通过。
